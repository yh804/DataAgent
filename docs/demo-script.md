# 3 分钟演示剧本

> 目标:让陌生人在 3 分钟内看懂「自然语言 → 计划审批 → 沙箱执行 → 可复现报告」。
> 前置:已按 `scripts/bootstrap.ps1` 启动服务,浏览器打开 `http://127.0.0.1:8000`,
> `data/processed/` 中有 `demo_sales.csv` 与 `demo_users_pii.csv`。
> 演示前请新建一个会话,避免历史信任状态让第一次审批被自动跳过。

## 时间分配

| 时间 | 步骤 | 要讲的一句话 |
|---|---|---|
| 0:00–0:20 | 开场 | AI 生成的分析代码不在主进程跑,只在 Docker 沙箱里跑 |
| 0:20–0:40 | 1 数据发现 | 先发现、后读取,模型只看到文件名 |
| 0:40–1:30 | 2 首次审批 + 执行 | 计划先给人看,批准后才生成并执行代码 |
| 1:30–2:00 | 3 追问自动通过 | 信任后的只读聚合不再打断人 |
| 2:00–2:25 | 4 高风险拦截 | 导出类问题重新要人确认 |
| 2:25–2:50 | 5 报告与数据版本 | 每个数字都能回溯到数据指纹与代码 |
| 2:50–3:00 | 6 历史与删除 | 轨迹可回放,会话可连轨迹一起删 |

## 步骤

### 1. 有哪些数据

- 操作:输入「有哪些数据」并回车。
- 预期现象:数秒内返回数据源清单(包含 `demo_sales.csv`、`demo_users_pii.csv`,
  以及 `data/processed/` 下已有的其他 CSV),不启动沙箱、不生成图表。
- 口播:「这一步只做发现:Agent 先登记目录里有哪些 CSV,模型拿到的是文件名而不是数据本身。」

### 2. 首次分析需要审批

- 操作:点输入框左侧 📎,在菜单「已有数据集」里选 `demo_sales.csv`(直接附加,不重新上传),
  再输入「按月看订单金额趋势并画图」,回车。
- 预期现象:
  1. 聊天区出现**折叠的审批卡**,一行显示「demo_sales.csv · 共 N 步」;
  2. 展开后能看到计划步骤,理由为「首次分析该数据集」;
  3. 勾选「本会话信任该数据集,不再询问」,点「运行」(或按 Enter);
  4. 节点 chip 依次点亮(planner → review_plan → code_analyst → summarize);
  5. 结果卡出现,右栏「报告」包含五节:一句话结论 / 关键发现 / 建议 / 局限与数据质量 /
     口径与数据版本;「图表」页出现按月折线图。
- 口播:「计划先给人看,是因为后面的代码由模型生成。批准后代码才进沙箱执行,
  数据只读挂载、没有网络、30 秒超时。」

### 3. 追问自动通过

- 操作:在同一会话输入「按渠道拆一下客单价」。
- 预期现象:**不弹审批卡**,结果卡上方出现「已自动通过」与理由「本会话已批准该数据集」;
  结果给出渠道对比表与差异结论。顶部的「计划审批」chip 显示「自动通过」。
- 口播:「信任只对只读聚合生效。策略仍会检查高风险词、PII 列和大文件,命中任何一条都回到人工确认。」

### 4. 高风险问题被拦回

- 操作:输入「把结果导出成 Excel」。
- 预期现象:再次出现审批卡,理由为「可能产生数据出口或副作用」;
  不要点运行,直接点「取消」结束这一步。
- 口播:「导出、保存、删除、批量这类词会触发数据出口风险,自动通过被立即收回。」

### 5. 报告与数据版本

- 操作:打开右栏「报告」,滚到「口径与数据版本」一节;再点「代码」页。
- 预期现象:能看到数据指纹(文件名@sha256 前 12 位)、行数(1200)、编码、文件大小与更新时间;
  「代码」页展示本次在沙箱里真实执行的 pandas 脚本。
- 口播:「结论不是一段无法验证的话:指纹定位数据版本,代码定位生成过程,
  `result.json` 的 stdout 能回溯每一个数字。」

### 6. 历史运行与删除会话

- 操作:点左侧「历史运行」中的一条 run,再打开右栏「Trace」页;
  最后点会话行右侧的垃圾桶图标,在确认弹窗中勾选「同时删除该会话生成的报告与图表」,
  点「永久删除」。
- 预期现象:Trace 页展示节点 / LLM / 工具耗时;删除成功后该会话从列表消失,
  右栏被清空,并出现「已删除会话」提示;历史运行列表中对应 run 也被移除。
- 口播:「删除不是隐藏:检查点、会话索引、trace、run 归档一起删,
  审批审计只脱敏问题文本、保留计数,便于讲清楚数据治理。」

## 可选加分:演示 PII 审批理由

1. 新建会话,点输入框左侧 📎 选择 `demo_users_pii.csv`,输入「看一下 demo_users_pii.csv 的注册用户数」;
2. 首次仍是「首次分析该数据集」,勾选信任并运行;
3. 再输入「统计 demo_users_pii.csv 的城市分布」。
- 预期现象:审批理由变为「疑似包含个人信息字段: 手机号, 邮箱」。
- 说明:策略只根据列名判定,数据值本身仍是不可达的假号,不会进入模型上下文。

## 演示兜底

- 若第 2 步没有出现审批卡:确认是新会话,且 `APPROVAL_POLICY` 未设为 `auto`;
  用 `APPROVAL_POLICY=confirm` 重启可强制每轮确认,便于讲解。
- 若执行失败且提示「沙箱不可用」:先确认 Docker Desktop 已启动、`docker info` 可用,
  再重跑 `scripts/bootstrap.ps1`。
- 演示过程中不要展示终端、`.env` 或任何密钥;截图前按
  [screenshot-checklist.md](screenshot-checklist.md) 裁掉无关区域。

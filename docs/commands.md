# Trae 命令（斜杠命令备份）

> Trae 的「命令」面板默认是空的，命令需要自己建。项目的 `.trae/rules/` 会被自动加载，
> 所以命令只放**偶尔才执行的整套流程**，日常规则不要塞进来。
>
> 建法：命令面板 → 右上「+ 创建」→ 选「项目」→ 把下面「内容」整段粘进正文。
> 本文件是备份：面板丢了、换电脑、命令被误删，都能从这里恢复。

---

## /验收（推荐，最常用）

**何时用**：改完一个功能、准备提交或演示之前。

**内容**：

```text
按顺序执行验收，任何一步失败就停下并报告失败原因，不要继续后面的步骤：

1. 跑测试：`.venv\Scripts\python.exe -m pytest -q`，要求全部通过。
2. 跑冒烟：`.venv\Scripts\python.exe scripts\smoke.py`，要求全绿。
3. 跑评测：`.venv\Scripts\python.exe eval\run_eval.py`，要求 8/8 PASS。
4. 对照 `.trae/rules/数据分析agent构建规则.md` 的硬性红线逐条检查本次改动：
   主进程是否执行了 AI 代码、数据是否进了 LLM 上下文、重试是否 ≤3、
   产物是否可复现、trace 是否记录。
5. 检查本次新增/修改的函数是否有 docstring（Args 逐参数说明）与必要的行内注释。
6. 按固定格式输出报告：
   - 通过项：测试数、冒烟项、评测条数
   - 失败项：命令、报错原文、定位到的文件:行号
   - 风险项：与红线冲突但暂未修的地方
```

## /讲解（可选）

**何时用**：想弄懂某段代码，或面试前复习。

**内容**：

```text
讲解我指定的文件或函数，按这个顺序：
1. 它在整条链路里的位置（谁调用它、它调用谁）。
2. 输入输出的数据结构（字段名、类型、单位）。
3. 关键分支和边界条件（失败、重试、空数据时怎么走）。
4. 如果删掉它，系统会在哪一步坏掉。
不要逐行翻译代码，只讲设计与取舍。
```

## /收尾（可选，作品集用）

**何时用**：功能冻结、准备截图和面试材料时。

**内容**：

```text
做发布前收尾：
1. 跑 /验收 的全部步骤。
2. 重新生成指标：`.venv\Scripts\python.exe scripts\collect_metrics.py`，
   确认 docs/metrics.md 与 README 的指标区块已更新。
3. 检查 docs/ 下 demo-script.md、interview-notes.md 里的命令与当前代码一致。
4. 列出本次改动涉及的文件清单，按「新增 / 修改 / 删除」分组。
5. 给出 3 条最值得在面试里讲的取舍（每条一句话：选了什么、放弃什么、为什么）。
```

## 什么时候用「全局」而不是「项目」

- 只对这个项目有意义的流程（上面的 /验收 依赖本项目的 pytest、smoke、eval 路径）→ 建在**项目**。
- 跨项目通用的话术（比如"用中文回答、先给结论"）→ 建在**全局**。

# 面试讲稿与高频追问

## 3 分钟口述稿(约 600 字)

我先说问题。做数据分析时,让大模型直接写结论,数字很容易编;让它直接跑代码,又有删库和外发风险。
我的方案是把两件事分开:模型只负责规划和写 pandas 代码,代码只在 Docker 沙箱执行,主进程不 exec 任何 AI 代码。

流程是五步:发现数据、生成计划、人工审批、沙箱执行、归档报告。审批不是每轮都拦:策略按信任状态、
高风险词、PII 列、50MB 大小判定,只读聚合自动通过,导出和敏感数据回到人工,审计表记录每次判定。

演示三步:问「有哪些数据」,秒回清单;问「按月看订单金额趋势并画图」,首次弹审批卡,
勾信任后执行,出五节报告和折线图;追问「按渠道拆一下客单价」,不弹卡,显示「已自动通过」;
再说「把结果导出成 Excel」,立刻被拦回确认。

最难的是安全与流畅的平衡。我保留 `APPROVAL_POLICY=confirm` 一键回到全人工,
策略异常也回退人工,绝不自动放行。

结果:111 条离线测试全绿,8 条端到端用例 8/8,单轮沙箱耗时中位 2.7 秒,
31 次审批决策里 auto 占 16.1%。

## 10 个高频追问

**1. 为什么用 LangGraph 而不是函数链?**
函数链无法在审批处暂停再恢复。StateGraph + SQLite checkpointer 用 `interrupt` 停下、
`Command(resume)` 续跑,状态可审计、可跨进程恢复。

**2. 为什么审批要分级?**
全自动会放行导出和 PII 操作,全人工每轮三次点击。规则按信任、高风险词、PII、50MB 分级,
31 次决策 auto 占 16.1%,风险项仍人工确认。

**3. 沙箱怎么防逃逸?**
`--network none`、`--memory 1g`、`--cpus 1`、30 秒超时、数据只读挂载;
主进程只用 `subprocess` 拉起容器,不执行任何 AI 代码。

**4. LLM 生成的代码错了怎么办?**
结构化错误分析带 `stderr` 回喂,最多重试 3 次;数据集缺失、Docker 未启动等标为不可重试,
直接结束并如实报告,不空转重试。

**5. 怎么保证数字不是编的?**
报告写 `文件名@sha256 前 12 位`,原始输出落 `result.json`;汇总只允许引用执行输出里的数字,
越界进 `warnings`,再由 `validate.py` 做数字溯源。

**6. 成本多少?**
指标显示单轮 token 均值 5,628(跳过 null 的 65 条样本),沙箱耗时中位 2.7 秒;
金额按实际模型单价换算,文档不写未经验证的金额。

**7. 为什么不用 Text2SQL / 现成 BI?**
Text2SQL 只覆盖数据库;这里要处理 CSV、画图、统计检验和人工审批。BI 要先建模型,
而目标是零建模的自然语言分析。

**8. 多用户怎么做?**
当前明确是本地单用户。多用户要加鉴权、每用户沙箱配额、任务队列、Postgres 检查点与对象存储,
并隔离各自的 `outputs/`。

**9. 怎么评测?**
111 条离线单元测试覆盖确定性逻辑,8 条端到端用例断言结论、图表与报告章节,
`smoke.py` 检查 import 链与关键结构,全部可接 CI 退出码。

**10. 如果重做会改什么?**
先补浏览器端自动化验收与更多数据格式;沙箱换 gVisor;评估集从 8 条扩到几十条,
并加人工标注的结论质量基线。

# 数据库问答历史化改造计划

## Context
当前 DB 问答只写 `outputs/db_queries.jsonl`(字段少、无接口、UI 不显示);只有成功链路会产生运行记录,
且运行记录里的数据集名是 `db_<label>_<时间戳>.csv`,看不出是哪个库/哪次查询。目标:
把每次数据库查询(成功/失败/超时/待澄清)变成「历史」页可见、可回溯的记录,并让运行归档保留原始结果,
即使 `data/processed` 被清理也能回看 SQL 与前 20 行。

## 已确认的现状
- `db_connections.append_query_audit(record)`:只写白名单字段(`_AUDIT_FIELDS`),追加写 `QUERIES_PATH`,无裁剪。
- `web/app.py::_prepare_database_question`:generate_sql → EXPLAIN → db_guard → `_run_db_query_with_progress`
  → 写 CSV(`_db_result_filename` → `db_<label>_<ts>.csv`)→ `append_query_audit` → 推 `sql` 事件 → 返回 extra。
  失败分支也写审计,但无 status/elapsed/csv_name;clarify 分支完全不写审计。
- `archive.py::_write_run_archive(run_id, run, report_text, code)` 写 result.json / report.md / code.py / report.html;
  `run["dataset"]` 即本轮 CSV 文件名。`_append_run_index` 写 `outputs/index.jsonl`。
- `web/routers/runs.py::list_runs` 直接倒序返回 index.jsonl 条目。
- `web/routers/databases.py` 承载 `/api/databases` CRUD;删除连接在 `delete_connection`。
- 历史页:`index.html #historyView` 内 `.history-grid` 两栏(会话 / 运行记录);`app.js setView("history")`
  调 `loadSessions()` + `loadRuns()`,运行行由 `loadRuns()` 渲染;`loadRunPanel(runId)` 打开结果页。
- 现有测试通过 `monkeypatch.setattr(app.db_connections, "append_query_audit", ...)` 拦截审计,
  因此 app.py 必须继续调用 `append_query_audit` 这个名字。

## 实现步骤

### 1. `db_connections.py`
1. 扩充 `_AUDIT_FIELDS` 为:`query_id, db_id, db_label, question, sql, ok, status, row_count,
   elapsed_ms, error, csv_name, run_id, cached, warnings, db_deleted`。
2. 新增 `_MAX_QUERY_RECORDS = 500` 与数据集名正则
   `^db_(?P<label>.+)_(?P<ts>\d{8}_\d{6})(?:_\d{3})?\.csv$`。
3. 新增 `record_query(record) -> str`:生成 `query_id`(uuid hex[:12])、`ts=_now()`,
   按白名单过滤后读全量 → 追加 → 只保留最后 500 条 → `_write_jsonl` 原子重写。返回 query_id。
4. `append_query_audit = record_query`(向后兼容:app 与旧测试继续用旧名)。
5. 新增:
   - `attach_run_id(query_id, run_id) -> bool`:按 query_id 找到记录;已有 run_id 则跳过(同一 run 只补一次);
     原子重写。
   - `read_queries(limit=50, db_id=None) -> list`:过滤 db_id、按 `ts` 倒序、截断,字段白名单输出
     (旧行补 `status`/`db_label` 默认值)。
   - `get_query(query_id)`、`find_query_by_csv(csv_name)`(归档回查用)。
   - `clear_queries() -> int`:原子清空文件并返回条数。
   - `parse_db_dataset(name) -> {label, ts} | None`(供 runs 列表与归档复用)。
6. `delete_connection` 成功后调用内部 `_mark_queries_deleted(id)`:把该 db_id 的记录标 `db_deleted=true`
   (不删除历史行)。

### 2. `archive.py`
1. 顶部 `import db_connections`。
2. 新增 `_archive_db_source(run_id, dataset, run_dir)`:
   - 文件名不匹配 `db_*.csv` → 返回 None;
   - `find_query_by_csv(dataset)` 回查审计;`db_query = {db_label, sql, row_count, csv_name}`,
     db_label 缺失时用 `parse_db_dataset` 推导;
   - 源 CSV 路径 = `SANDBOX_DATA_DIR` 或 `data/processed` / dataset,存在则 `shutil.copy2` 到
     `runs/<run_id>/source.csv`(失败只记 warning,不抛)。
3. `_write_run_archive` 在写 result.json 前调用;有结果时 `run["db_query"] = db_query`
   (result.json 自动带上,同时供 index 使用)。
4. `_append_run_index` 增加 `db_label`、`db_row_count`、`sql_available`(`bool(db_query.sql)`)。

### 3. `web/routers/runs.py`
`list_runs` 返回前对每条 item:
- 用 `db_connections.parse_db_dataset(item["dataset"])` 兜底 `db_label`(旧 index 行没有该字段);
- 补 `db_row_count`(默认 None)与 `sql_available`(默认 False)。

### 4. `web/app.py`
1. 新增 `_DB_QUERY_IDS: dict[str, str]` 记录本轮审计 query_id。
2. `_prepare_database_question`:
   - 记录 `query_started = time.monotonic()`(执行查询前);失败时计算 elapsed_ms;
   - clarify 分支写一条 `status="clarify"`(ok=False,sql 空)记录;
   - 成功记录补 `db_label/status="ok"/elapsed_ms/csv_name/error=""`,保存返回的 query_id;
   - 失败记录补 `db_label/status(timeout|failed)/elapsed_ms/error`;
   - 失败与 clarify 清理 `_DB_QUERY_IDS`。
3. 新增 `_backfill_db_run_id(thread_id, run_id)`:查到 query_id 时调 `db_connections.attach_run_id`,
   异常只记日志。在 `_execute_question`(pre-auto、post-plan auto、无中断分支)与 `_execute_approval`
   拿到最终 state 后调用;非数据库问题分支清空 `_DB_QUERY_IDS`。

### 5. `web/routers/databases.py`
新增三个端点(不改既有 CRUD):
- `GET /api/db/queries?limit=50&db_id=` → `run_in_threadpool(connections.read_queries, ...)`;
- `DELETE /api/db/queries` → `clear_queries()`,并向 `outputs/deletions.jsonl` 追加
  `{ts, kind:"db_queries", removed}`(不删运行记录);
- `GET /api/db/queries/preview?run_id=&csv_name=&limit=20`:
  优先 `outputs/runs/<run_id>/source.csv`,其次 `SANDBOX_DATA_DIR`/`data/processed` 下同名 CSV;
  用 `pandas.read_csv(nrows=limit)` + `frame.to_json(orient="records")` 输出
  `{available, columns, rows, source}`;run_id 与 csv_name 都做白名单/纯文件名校验。
- 模块内新增 `PROJECT_ROOT`/`RUNS_ROOT`/`DELETIONS_PATH` 常量,避免与 `web.app` 循环导入。

### 6. 前端 `index.html` + `theme.css` + `app.js`
1. `index.html`:右侧历史列改为「数据库查询」列表在上、「运行记录」在下;新增第三栏
   `#dbQueryDetail`(默认 hidden),`.history-grid` 加 id 与 `has-detail` 类切换。
2. `theme.css`:新增 `.history-grid.has-detail` 三列布局、状态徽章(成功/失败/超时/待澄清)、
   SQL 代码块、预览表格、详情头/操作区样式;≤900px 时退化为单列。
3. `app.js`:
   - `setView("history")` 同时 `loadDbQueries()`;init 不额外调用。
   - `loadDbQueries()`:GET 列表,逐行渲染 时间 · 库名 · 截断问题 · 状态徽章 · 行数 · 耗时;
     空状态文案「还没有数据库查询记录；在输入框选一个库提问后会出现在这里」。
   - 点击行 → `showDbQueryDetail(q)`:`#dbQueryDetail` 填充状态、时间、库名、错误原因
     (失败/超时)、完整 SQL + 复制按钮、前 20 行表格(调 preview 接口)、
     `run_id` 存在时显示「打开运行」按钮(调 `loadRunPanel(runId)`);`.history-grid` 加 `has-detail`。
   - `loadRuns()`:dataset 匹配 `db_*_<ts>.csv` 时额外显示 `db_label`(有 `db_row_count` 时显示
     `db_label: row_count`),`title` 设为原始文件名。

### 7. 测试
- 新建 `tests/test_db_queries_api.py`(TestClient + monkeypatch `QUERIES_PATH`):
  写入成功/失败两条 → `GET /api/db/queries` 倒序且无密码;`attach_run_id` 后成功记录带 run_id;
  `DELETE /api/db/queries` 只清审计。
- 新建 `tests/test_run_archive_db_source.py`(monkeypatch `archive.RUNS_DIR`、`db_connections.QUERIES_PATH`、
  `SANDBOX_DATA_DIR`):db_* 数据集归档后有 `source.csv` 与 `result.json.db_query`;
  普通 CSV 不产生 `db_query`。
- 跑全量 `pytest`(基线 305 passed, 3 skipped)。

# 数据分析 Agent 构建规则(通用版)

> 版本:v1.2
> 适用范围:自然语言驱动的数据分析 Agent,不限定业务领域,覆盖结构化 / 半结构化数据。
> 说明:本文件约束"开发本项目的 AI"(写代码、改架构、审代码时遵守);Agent 运行时的行为由 `prompts.py` 中的系统提示词决定,两者需保持一致。

## 0. 目标与边界

**目标闭环**:理解问题 → 发现/选择数据 → 制定计划 → 生成并执行代码 → 校验结果 → 汇总结论与图表。

| 维度 | 适用 | 暂不适用 |
|---|---|---|
| 数据形态 | 表格、关系库、JSON/日志 | 图像、音视频、长文档语义 |
| 数据规模 | 单机内存可容纳(大表用 DuckDB/数据库下推) | 实时流、超大规模训练 |
| 分析类型 | 查询、聚合、透视、时序、对比、相关、可视化、轻量统计 | 深度建模、在线推理 |

术语:**主进程**=运行状态图、调用 LLM 与工具的宿主;**沙箱**=AI 生成代码的唯一执行环境;**数据源**=文件、数据库表、对象存储、API。

## 1. 总体原则

### 1.1 红线(任何情况下不得违反)

1. 主进程禁止执行 AI 生成代码,`exec`/`eval`/`compile`/`subprocess` 只能发生在沙箱内。
2. 读取数据前必须先经发现工具登记数据源。
3. 全量数据禁止进入 LLM 上下文,只传 schema、摘要、抽样样本。
4. 所有循环必须有硬性上限(次数 / 时间 / 成本)。
5. 沙箱默认无外网、无环境变量、无密钥。
6. 每个数字结论必须能回溯到代码与数据版本。
7. 异常必须显式报告,禁止静默失败或编造结果。
8. 源数据只读,产物写入独立输出目录。

### 1.2 设计原则

最小闭环优先;工具即边界;状态可持久、可中断、可恢复;行为可观测;结果可评估。

## 2. 编排框架

1. 使用 LangGraph `StateGraph`,不用无状态函数链替代。
2. 状态强类型(`TypedDict`),至少含:`question`、`messages`(add_messages)、`data_sources`、`plan`、`code`、`exec_result`、`error_analysis`、`iteration`、`final_answer`。
3. 必须挂 `checkpointer`(SQLite/Postgres),支持中断、恢复、人工审批。
4. 节点职责单一,建议:数据发现、计划、代码生成、沙箱执行、反思(校验/重试)、汇总。发现节点可并入计划节点,但读取前必须完成登记。
5. 锁定 LangGraph 及依赖版本,避免行为漂移。
6. 全链路追踪二选一:自建 `trace.py`(落 `outputs/traces/*.json`)或 LangSmith / Langfuse;同一项目不要两套并存。

## 3. 数据处理

1. 默认 pandas;数据量超阈值(如 >100 万行或内存告警)时降级 DuckDB/Polars,数据库场景优先 SQL 下推。
2. DataFrame 禁止整体进 prompt,只传 `head(n)`、`describe()`、schema。
3. 时间列统一转 `datetime`,禁止字符串比较;金额注意精度与舍入。
4. 中文内容统一 UTF-8,读取时显式声明 `encoding`;无表头文件按位置命名 `col_1..col_n`。
5. 大结果集先聚合/抽样再返回,禁止把全量结果回传主进程。

## 4. 沙箱

1. `execute_code` 是 AI 代码的唯一执行入口。
2. 硬约束:CPU/内存上限、单次超时(默认 30s)、数据只读挂载、产物写 `outputs/`、默认无外网。
3. 禁止向沙箱暴露环境变量、密钥、云凭据。
4. 返回结构化结果:`{stdout, stderr, return_value, charts[], files[], duration_ms, exit_status}`。
5. 运行时与依赖由白名单决定,Agent 不得自行 `pip install`。

## 5. 数据访问

1. 先发现后读取;未登记的数据源,读取工具直接拒绝。
2. 发现工具返回统一元数据:`{id, name, kind, format, row_count, size_bytes, schema, updated_at, checksum}`。
3. 先看 schema 再读数据:`describe_dataset` 返回列名、类型、空值率、抽样样本。
4. 源数据只读,产物写独立 `outputs/`。
5. 记录文件哈希与更新时间,保证可复现。

## 6. 上下文管理

1. 只放高信息密度内容:问题、schema 摘要、抽样、执行结果摘要。
2. 长对话做压缩与摘要,避免溢出。
3. 大 JSON / 大 DataFrame 不原文塞入,改结构摘要或文件引用。
4. 工具输出截断(如 stdout 只留尾部),超长内容落盘只给路径。

## 7. 代码风格与注释

1. 遵循 PEP 8;注释用中文,标点用英文标点;字符串、列名、参数名保持原样。
2. 每个函数必须有 docstring:用途 + `Args`(逐参数"含义 + 单位/取值 + 默认行为")+ `Returns`;无参数省略 `Args`;参数格式 `参数名: 含义(单位, 可选值, 默认行为)`。
3. 非默认参数在调用处加行内注释,说明其在本数据集语境下的含义;默认参数不注释。
4. 魔法数字提取为命名常量,并在定义处注释来源与口径。
5. 禁止逐行翻译式注释;只写"为什么、参数含义、边界条件、统计口径"。
6. 注释与代码同步:改签名、改默认值时同一改动内更新 docstring 与注释。
7. 注释中禁止出现真实数据(手机号、身份证、姓名、密钥),举例用占位符。
8. 生成脚本额外要求:开头注释块写明输入文件与编码、关键列假设、输出路径、复现方式;注释密度 ≤30%;docstring ≤5 行;脚本可独立运行。
9. 图表代码与计算代码解耦,图表统一输出到 `outputs/`。

## 8. 错误处理与重试

1. 报错先输出【错误原因分析】(错误类型、触发点、根因、修复方案),再改代码。
2. 同一错误连续重试 ≤3 次;单会话迭代有上限;超限停止并如实报告。
3. 重试必须携带上一次 `stderr` 与根因分析,禁止盲猜重写。
4. 区分可修复错误与不可修复错误(数据缺失、权限不足),后者直接终止上报。

## 9. 安全

1. 沙箱禁访危险路径(`~/.ssh`、`/etc/passwd`、`C:\Windows`、`/proc`、`/sys`)。
2. 限制输出文件大小与数量,大结果集强制抽样。
3. 疑似 PII(手机号、身份证、银行卡、邮箱)输出前提示或脱敏。
4. 网络默认关闭,外部依赖走白名单。
5. 所有工具调用与代码执行留审计记录。

## 10. 验证与可复现

1. 结论 = 结论 + 关键中间结果 + 图表(如有)。
2. 数字必须能回溯到产生它的代码与数据版本。
3. 聚合结果做 sanity check:行数、去重数、空值比例、量级是否合理。
4. 输出结构化(表格 + 要点 + 图表),便于人审与程序校验。

## 11. 可视化

1. 用白名单库生成,输出到 `outputs/`,以文件路径引用,不以 base64 进上下文。
2. 按数据特征选图:趋势折线、占比饼/柱、分布直方、关系散点。
3. 必须有标题、轴标签、图例;中文字体需正确配置。

## 12. 可观测性

1. 全链路 trace:节点输入/输出/耗时/工具调用/token 用量。
2. 支持按会话 ID 回放轨迹。
3. 记录成本指标(token、沙箱时长),用于成本治理。

## 13. 评估与测试

1. 维护回归评估集:问题 + 期望断言。
2. 结果比对 + LLM-as-judge 双轨;judge 默认关闭,按需开启。
3. 每次改规则/提示词/代码后跑回归。
4. 关键路径(发现、执行、重试)必须有单元测试。

## 14. 人机协作(HITL)

1. 长耗时、高成本、危险操作前用 `interrupt` 请求确认。
2. 分析计划允许用户 approve / edit 后执行。
3. 任意节点可中断,从检查点恢复。

## 15. 性能与成本

1. 优先下推计算,减少数据搬运。
2. 探索阶段采样,确认后跑全量。
3. 设置会话 token 预算与执行时长预算,超限降级或终止。
4. 缓存可复用的数据发现结果与 schema。

## 16. 隐私与合规

1. 最小权限,只访问白名单数据源。
2. PII 进入分析前识别并提示脱敏。
3. 审计日志保留数据访问与执行记录。

## 17. 推荐技术栈

| 层次 | 推荐 |
|---|---|
| 编排 | LangGraph(StateGraph + checkpointer + interrupt) |
| 可观测 | 自建 trace.py,或 LangSmith / Langfuse |
| 沙箱 | Docker / E2B,唯一执行入口 |
| 数据处理 | pandas 为主,DuckDB / Polars 降级 |
| 可视化 | Matplotlib / Plotly |
| LLM | 按代码生成能力选型 |

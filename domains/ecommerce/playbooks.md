# 电商领域包 · 分析套路

> 版本:v0.1 · 指标定义见 [metrics.yaml](metrics.yaml),字段见 [schema.md](schema.md)。
> 每个套路都必须先声明口径状态:引用 draft 指标时,报告需在「局限与数据质量」中提示「口径待确认」。
> 本文件只用反引号包裹指标 id;列名一律用「」标注,避免与指标 id 混淆。

## P1 日销趋势

- **触发问法**:「按天看销售额趋势」「最近一个月 GMV 怎么走」「哪几天卖得最好」
- **步骤**:
  1. 确认时间字段:按 `orders.订单日期` 还是 `orders.支付时间`;全报告统一。
  2. 排除测试单、刷单、内部账号、测试账号;只保留支付口径订单。
  3. 按日汇总 gmv、order_count;同时算 aov,避免「订单数涨、客单跌」被忽略。
  4. 标注促销日与周末;找出峰值日与断崖日,并给出前后 3 天对比。
- **必报指标**:`gmv`、`order_count`、`aov`
- **推荐图表**:日粒度折线图(双轴:GMV 与订单数) + 促销日竖线标注;必要时叠加 7 日移动平均。
- **常见坑**:
  - 用「订单日期」算 GMV、用「支付时间」算复购,两个口径混在一张报告里;
  - 促销日只看绝对峰值,不看活动结束后的回落;
  - 异常金额单不剔除也不说明,导致峰值被单笔订单主导;
  - 缺失渠道的订单被静默丢弃,导致总量少算约 1%。

## P2 渠道转化漏斗

- **触发问法**:「哪个渠道转化率最高」「各渠道流量效率对比」「直播和小程序哪个更值得投」
- **步骤**:
  1. 用 `traffic.csv`,按 `渠道`(必要时叠加 `实验组`)汇总曝光、访问、加购、下单、支付。
  2. 依次计算曝光→访问、访问→加购、加购→下单、下单→支付的分步转化,再给整体支付转化率。
  3. 对渠道间差异做两比例 z 检验,给出绝对差(pp)、相对提升、95% 置信区间与 p 值。
  4. 与订单表的渠道结构交叉核对,说明流量口径与订单口径的差异。
- **必报指标**:`pay_conversion_rate`、`cart_add_rate`、`order_count`
- **推荐图表**:漏斗条形图(分渠道) + 转化率点图(带 95% CI 误差棒)。
- **常见坑**:
  - 把实验组与对照组的访问人数直接相加,重复计算线上商城流量;
  - 线下门店的「访问人数」口径与线上不同,直接横向排名;
  - traffic 与 orders 不做对账,却声称两者一致;
  - 只报转化率不报样本量,小样本渠道被误判为「最优」。

## P3 品类结构

- **触发问法**:「哪些品类贡献最多 GMV」「品类占比变化」「服饰和数码哪个更赚钱」
- **步骤**:
  1. 以 `orders.csv` 的干净支付订单为基础,关联 `order_items.csv`,再关联 `products.csv` 取品类。
  2. 按品类汇总 gmv、order_count、aov、attach_rate;同时算 GMV 占比与订单数占比。
  3. 判断「高 GMV 低订单」与「低 GMV 高订单」两类品类,并给同比 / 环比变化。
  4. 若需要利润视角,用商品成本价做粗算,并在报告中注明「非财务口径」。
- **必报指标**:`gmv`、`order_count`、`aov`、`attach_rate`
- **推荐图表**:品类 GMV 占比横向条形图(按金额降序) + 订单数/GMV 四象限散点。
- **常见坑**:
  - 明细表没有品类字段,忘记关联商品表就按商品ID分组;
  - 把赠品明细计入品类 GMV;
  - 退款订单不做处理,品类 GMV 偏高;
  - 品类占比用订单数代替金额,结论方向相反。

## P4 价格带分析

- **触发问法**:「不同价格带的销量分布」「我们的主力价格带在哪」「提价空间有多大」
- **步骤**:
  1. 以 `products.单价` 划分价格带:`<100`、`100–299`、`300–599`、`≥600` 元(边界待确认)。
  2. 明细金额用 `order_items.明细金额`;订单级用 `orders.订单金额`;两者不可混用。
  3. 按价格带汇总 gmv、order_count、aov、连带率,并给各价格带的退款率。
  4. 说明优惠与运费对实付价格带的影响;必要时用实付单价重复一次。
- **必报指标**:`gmv`、`order_count`、`aov`、`attach_rate`、`refund_rate`
- **推荐图表**:价格带 GMV/订单数分组柱状图 + 客单价折线叠加;必要时画价格分布直方图。
- **常见坑**:
  - 用订单总金额除以件数当「单价」,与商品标准单价混为一谈;
  - 价格带边界不写明,读者无法复现;
  - 忽略优惠分摊(当前数据 `优惠分摊` 全为 0),实付价格带与吊牌价带不一致;
  - 异常金额单落入最高价格带,拉高该带客单价。

## P5 新老客拆分

- **触发问法**:「新客和老客的客单价差多少」「增长靠拉新还是靠复购」「新客占比是不是太高」
- **步骤**:
  1. 直接使用 `orders.新客` 标记;先报告该标记的定义(数据集内首笔干净支付订单)。
  2. 按新客 / 老客分组,汇总 gmv、order_count、aov、refund_rate。
  3. 给出新客占比(订单口径),并同时给用户口径,避免两种口径被混用。
  4. 按渠道与品类交叉,判断拉新主要来自哪里。
- **必报指标**:`new_customer_ratio`、`aov`、`gmv`、`refund_rate`
- **推荐图表**:新老客分组柱状图(客单价 + 订单数双轴);新客占比趋势折线。
- **常见坑**:
  - 新客标记依赖数据集内的历史,首次导入时新客占比天然偏高;
  - 同一天多单只有最早一单算新客,其余算老客;
  - 用「订单占比」和「用户占比」混着说,数字对不上;
  - 新客首单退款后仍被计为新客,未做说明。

## P6 复购 / cohort 留存

- **触发问法**:「复购率多少」「用户买完多久会再买」「按首单月份看留存」
- **步骤**:
  1. 定义干净支付订单(排除测试单、刷单、内部账号、测试账号);确认是否剔除退款单。
  2. 计算 repurchase_rate:窗口内有 ≥2 笔干净支付订单的用户占比。
  3. 计算 repurchase_interval:相邻订单天数差,报中位数与 P25/P75,并给参与用户数。
  4. 做 cohort:按用户首单月份分组,观察后续每个月的留存率;标注右删失月份。
- **必报指标**:`repurchase_rate`、`repurchase_interval`、`new_customer_ratio`
- **推荐图表**:cohort 热力图(首单月份 × 后续月份) + 复购间隔箱线图 / 直方图。
- **常见坑**:
  - 观察窗不足(3 月入场的用户还没机会复购)却不标注,复购率被低估;
  - 同日多单造成 0 天间隔,拉低复购间隔中位数;
  - 把「复购率」写成「留存率」,两者分母不同;
  - cohort 热力图把未到期月份画成 0%,误读为「流失」。

## P7 RFM 分层

- **触发问法**:「把用户按价值分层」「哪些用户该召回」「高价值用户有什么特征」
- **步骤**:
  1. 以干净支付订单为基础,按用户计算 R(最近一次支付距今天数)、F(支付订单数)、M(支付金额合计)。
  2. 用分位数(如五分位)或业务阈值切分 R/F/M;阈值必须写进报告,属于 draft 业务决策。
  3. 组合成 8 类或 5 类用户群,给出每类人数、GMV 占比、平均客单价、复购间隔。
  4. 输出召回 / 维护 / 观察 / 放弃四类行动建议,不要只给编号。
- **必报指标**:`gmv`、`order_count`、`repurchase_interval`、`repurchase_rate`
- **推荐图表**:RFM 三维散点(R/F/M)+ 分群人数与 GMV 占比条形图。
- **常见坑**:
  - 用注册日期代替最近购买日期;
  - 阈值拍脑袋且不写清,不同人算出的分层不可比;
  - 只按 M 分层,忽视 R 与 F;
  - 内部账号混入高价值用户群。

## P8 AB 实验

- **触发问法**:「实验组和对照组的支付转化率差多少」「这个活动有没有效果」「差异显著吗」
- **步骤**:
  1. 先做 SRM 检查:按分组样本量做卡方拟合优度,期望为总量 / 组数;p < 0.001 标注「分流异常」。
  2. 检查重复曝光、分组与曝光不匹配行数;报告两者是否重叠。
  3. 计算两组访问人数、支付人数、支付转化率(6 位小数)、绝对差(pp)、相对提升、RR。
  4. 做两比例 z 检验,给出 z、双侧 p 值、差值 95% 置信区间;区分统计显著与实际重要。
  5. 若实验跨 ≥3 天,按「日期 × 分组」给每日样本量与转化率,识别新鲜度效应。
- **必报指标**:`pay_conversion_rate`、`cart_add_rate`、`order_count`
- **推荐图表**:转化率点图(带 95% CI)+ 每日转化率折线(实验组 vs 对照组)+ SRM 样本量条形图。
- **常见坑**:
  - 只报 p 值,不报绝对差与置信区间,读者无法判断业务价值;
  - 把「统计显著」写成「显著提升」,夸大结论;
  - 不做 SRM,分流本身有偏却归因给实验;
  - 本数据集只有线上商城做了实验组拆分,其他渠道为「未分流」,不能整表对比。

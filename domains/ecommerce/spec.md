# 电商领域包 · 业务规格

> 版本:v0.1 · 状态:草案(业务口径未确认)
> 适用范围:`domains/ecommerce/` 下的文档与合成数据;不包含任何运行时代码改动。

## 1. 业务背景

本包面向一个虚构的中型电商品牌:同时经营**线下门店、线上商城、小程序、直播**四个渠道,覆盖**服饰、美妆、食品、家居、数码**五个品类,分析区间为 2026-01-01 至 2026-03-31(90 天)。品牌每周围绕销量、渠道效率、品类结构、新老客与复购开经营会,但各团队对 GMV、客单价、复购率的口径理解不一致,导致同一个数字在不同报告里对不上。本包的目标不是给出答案,而是把「问题 → 指标 → 数据 → 分析套路」的映射固定下来,并明确哪些口径仍需业务确认。

数据全部为合成数据,**不含任何真实公司、用户或交易信息**;生成脚本固定随机种子,可逐字节复现。

## 2. 报告读者

| 角色 | 关注点 | 报告用途 |
|---|---|---|
| 电商运营负责人(主读者) | 增长来自哪里、投入该加码还是收缩 | 周会决策、月度复盘 |
| 渠道运营 | 各渠道流量与支付转化、活动效果 | 渠道预算分配 |
| 商品运营 | 品类结构、价格带、连带率 | 选品与定价 |
| 用户运营 | 新客占比、复购率、RFM 分层 | 拉新与召回策略 |
| 数据分析师 | 口径是否一致、数字能否回溯 | 报告复核与回归 |

报告应沿用本项目既有风格:结论先行,必须含「一句话结论 / 关键发现 / 建议 / 局限与数据质量 / 口径与数据版本」,数字只能来自本次执行输出。

## 3. 最重要的 3 个决策问题

### Q1 增长到底来自哪里?

- 需要回答:GMV 增长由**渠道、品类、新客、客单价、订单频次**中的哪几项驱动?
- 必报指标:`gmv`、`order_count`、`aov`、`new_customer_ratio`
- 对应套路:P1 日销趋势、P3 品类结构、P5 新老客拆分

### Q2 哪些渠道和品类应该加码或收缩?

- 需要回答:各渠道的流量效率(转化)与成交质量(退款、客单价)是否匹配?哪些品类靠低价走量、哪些靠高价拉客单?
- 必报指标:`pay_conversion_rate`、`cart_add_rate`、`refund_rate`、`aov`
- 对应套路:P2 渠道转化漏斗、P4 价格带、P8 AB 实验

### Q3 复购与用户价值该如何分层运营?

- 需要回答:复购率与复购间隔处于什么水平?哪些用户值得召回、哪些是一次性客户?
- 必报指标:`repurchase_rate`、`repurchase_interval`、`new_customer_ratio`、`gmv`
- 对应套路:P6 复购 / cohort 留存、P7 RFM 分层

指标选择与拆解见 [frameworks.md](frameworks.md)。

## 4. 范围内

- 结构化表格数据(CSV),单机 pandas 可容纳;
- 描述性统计、聚合、透视、趋势、对比、相关、轻量显著性检验(两比例 z 检验);
- 面向运营读者的 Markdown 报告与图表;
- 数据质量检查:测试单、刷单、0 元单、缺失值、异常金额。

## 5. 明确不做(非目标)

| 非目标 | 原因 |
|---|---|
| 接入真实交易 / 用户数据 | 本轮只做合成演示数据,避免编造真实数据 |
| 客诉率、客服工单分析 | 当前五张表没有工单表,无法计算;需要后续补数据源 |
| 因果推断、增量归因、营销 mix modeling | 观测数据无法支撑因果结论,超出本包范围 |
| 销量预测、推荐算法、用户画像建模 | 属于建模任务,不是描述性分析 |
| 实时看板与流式处理 | 本包只覆盖离线批处理 |
| PII 明细分析 | 用户表手机号为脱敏假值,只用于演示 PII 识别与脱敏 |
| 修改 Agent 运行时(prompt / 节点 / 工具) | 本轮只交付文档与数据,接入方式见 README |

## 6. 术语表

| 术语 | 本包定义 | 备注 / 状态 |
|---|---|---|
| GMV | 支付口径的商品交易总额,默认取 `orders.支付金额` 求和,并排除测试单、刷单、内部账号 | 是否扣退款待确认(draft) |
| 订单金额 | 应付金额 = 商品金额 + 运费 − 优惠金额 | 未支付订单也有应付金额 |
| 支付金额 | 实际支付成功的金额;待支付 / 已取消为 0 | GMV 默认取此列 |
| 净 GMV | GMV − 退款金额 | 本包候选口径,尚未拍板 |
| 订单数 | 发生过支付的订单数(含全额退款订单) | `order_count` 标 confirmed |
| 客单价(AOV) | GMV / 支付订单数 | 是否用净 GMV 待确认(draft) |
| 支付转化率 | 支付人数 / 访问人数(按日期、渠道、实验组聚合) | 分母口径待确认(draft) |
| 加购转化率 | 加购人数 / 访问人数 | 是否含重复加购待确认(draft) |
| 退款率 | 候选 A:退款订单数 / 支付订单数;候选 B:退款金额 / 支付金额 | 双口径并列,主口径待确认(draft) |
| 复购率 | 窗口内干净支付订单数 ≥2 的用户 / 有 ≥1 笔干净支付订单的用户 | 窗口长度待确认(draft) |
| 复购间隔 | 同一用户相邻两笔干净支付订单的天数差,默认报中位数与四分位 | 是否只算首单→二单待确认(draft) |
| 新客 | 用户在本数据集内的首笔干净支付订单 | 是否改用「注册 30 天内首单」待确认(draft) |
| 新客占比 | 新客支付订单数 / 支付订单数 | 订单口径 vs 用户口径待确认(draft) |
| 连带率 | 订单明细件数(不含赠品)/ 干净支付订单数 | 是否用品类数口径待确认(draft) |
| 0 元单 | 支付时间为非空、支付金额为 0 的订单(整单优惠覆盖) | 是否计入订单数待确认(draft) |
| 测试单 | `orders.是否测试单 = 是`,含内部 / 测试账号下的订单 | 默认排除 |
| 刷单 | `orders.是否刷单 = 是` | 默认排除,但保留审计 |
| 价格带 | 按商品标准单价分档:<100 / 100–299 / 300–599 / ≥600 元 | 分档边界待确认(draft) |
| Cohort | 按用户首笔干净支付订单所在月份分组,观察后续月份留存 | 窗口右删失需在报告中声明 |
| RFM | 最近一次购买(R)、购买频次(F)、累计金额(M) | 分层阈值待确认(draft) |
| SRM | 实验分流比例异常(Sample Ratio Mismatch) | AB 套路的前置检查 |
| 口径 | 指标的计算范围、过滤条件、时间归属与去重方式 | 每个指标必须写明 |

## 8. 数据与复现

- 数据目录:`examples/`,五张表,UTF-8 with BOM,逗号分隔;
- 生成脚本:`examples/generate_demo_data.py`,随机种子 `20260101`;
- 数据规模:orders 2000 行、order_items 3786 行、users 1500 行、products 120 行、traffic 450 行;
- 复现方式:`python domains/ecommerce/examples/generate_demo_data.py`;
- 自检方式:`python domains/ecommerce/check_package.py`。

# 电商领域包 · 数据模型

> 版本:v0.1 · 对应数据:`examples/*.csv`(合成数据,UTF-8 with BOM,逗号分隔)
> 本文件是字段契约:生成脚本、自检脚本、后续接入都以此为准。

## 1. 文件与表总览

| 文件 | 表名 | 粒度 | 主键 | 行数(当前) |
|---|---|---|---|---|
| `examples/orders.csv` | 订单表 | 一行一个订单 | `订单号` | 2000 |
| `examples/order_items.csv` | 订单明细表 | 一行一个订单行 | `(订单号, 明细行号)` | 3786 |
| `examples/users.csv` | 用户表 | 一行一个用户 | `用户ID` | 1500 |
| `examples/products.csv` | 商品表 | 一行一个商品(SKU) | `商品ID` | 120 |
| `examples/traffic.csv` | 流量表 | 一行一个日期×渠道×实验组 | `(日期, 渠道, 实验组)` | 450 |

所有文件编码为 `utf-8-sig`(带 BOM),与项目现有 `examples/demo_sales.csv` 一致;读取时显式声明 `encoding="utf-8-sig"`。

## 2. 订单表 `orders.csv`

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| 订单号 | string | 否 | 主键,格式 `SO{YYYYMMDD}{6 位序号}` |
| 用户ID | string | 否 | 外键 → `users.用户ID` |
| 订单日期 | date(`YYYY-MM-DD`) | 否 | **下单日期**,只有日期没有时间 |
| 支付时间 | datetime(`YYYY-MM-DD HH:MM:SS`) | 是 | **支付成功时间**;待支付 / 已取消为空 |
| 发货时间 | datetime | 是 | **出库时间**;未发货、退款单、1% 缺失为空 |
| 订单状态 | string | 否 | 已完成 / 已发货 / 已支付 / 待支付 / 已取消 / 已退款 / 退款中 |
| 渠道 | string | 是 | 线下门店 / 线上商城 / 小程序 / 直播;约 1% 缺失 |
| 地区 | string | 否 | 华北 / 华东 / 华南 / 华中 / 西南 |
| 商品金额 | float(2 位小数) | 否 | 明细金额合计,不含运费、优惠前 |
| 运费 | float | 否 | 线下门店为 0;商品金额 ≥ 99 元为 0,否则 10 元 |
| 优惠金额 | float | 是 | 整单优惠;约 2% 缺失 |
| 订单金额 | float | 否 | 应付金额 = 商品金额 + 运费 − 优惠金额 |
| 支付金额 | float | 否 | 实付金额;未支付订单为 0 |
| 退款金额 | float | 否 | 已退款为全额;退款中与未退款为 0 |
| 是否退款 | string(是/否) | 否 | 已退款、退款中为「是」 |
| 新客 | string(是/否) | 否 | 该用户在本数据集内首笔干净支付订单标记为「是」 |
| 是否测试单 | string(是/否) | 否 | 测试单 / 内部账号 / 测试账号订单为「是」 |
| 是否刷单 | string(是/否) | 否 | 约 1.2% 订单被标记 |
| 活动ID | string | 是 | 新客券 / 满减券 / 直播专享 / 会员日;约 70% 为空 |

## 3. 订单明细表 `order_items.csv`

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| 订单号 | string | 否 | 外键 → `orders.订单号` |
| 明细行号 | int | 否 | 订单内行号,从 1 开始,与订单号共同构成主键 |
| 商品ID | string | 否 | 外键 → `products.商品ID` |
| 数量 | int | 否 | 购买件数,1–3;赠品固定为 1 |
| 单价 | float | 否 | 下单时单价;赠品为 0 |
| 明细金额 | float | 否 | 单价 × 数量;赠品为 0 |
| 优惠分摊 | float | 否 | 当前数据统一为 0,保留字段供后续分摊 |
| 是否赠品 | string(是/否) | 否 | 约 3% 明细为赠品 |

> 明细表不冗余商品名称与品类:品类结构分析必须经 `商品ID` 关联 `products.csv`。

## 4. 用户表 `users.csv`

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| 用户ID | string | 否 | 主键,格式 `U{6 位序号}` |
| 注册日期 | date | 否 | 注册自然日;所有订单日期均不早于该日期 |
| 注册渠道 | string | 否 | 四个渠道之一 |
| 地区 | string | 否 | 与订单表地区一致 |
| 会员等级 | string | 否 | 普通 / 银卡 / 金卡 / 黑卡 |
| 性别 | string | 否 | 男 / 女 / 未知 |
| 年龄 | int | 是 | 18–65;约 3% 缺失 |
| 手机号 | string | 否 | **脱敏假值**,格式 `138****NNNN`,不可达、不对应真实用户 |
| 是否内部账号 | string(是/否) | 否 | 前 8 个用户为内部账号 |
| 是否测试账号 | string(是/否) | 否 | 第 9–14 个用户为测试账号 |

> `手机号` 只用于演示 PII 识别与脱敏;任何分析报告不得输出完整号码。

## 5. 商品表 `products.csv`

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| 商品ID | string | 否 | 主键,格式 `P{3 位序号}` |
| 商品名称 | string | 否 | 合成名称,如 `合成商品-001` |
| 品类 | string | 否 | 服饰 / 美妆 / 食品 / 家居 / 数码 |
| 子品类 | string | 否 | 品类下二级分类 |
| 品牌 | string | 否 | 合成品牌A–E |
| 单价 | float | 否 | 标准售价(吊牌价) |
| 成本价 | float | 否 | 标准售价的 30%–60% |
| 上架日期 | date | 否 | 2025-01-01 至 2026-02-28 |
| 是否在售 | string(是/否) | 否 | 约 92% 为「是」 |

**价格带口径(草案)**:按 `products.单价` 分档,`<100`、`100–299`、`300–599`、`≥600` 元。分档边界属于业务决策,状态 draft,确认前报告必须同时写出边界。

## 6. 流量表 `traffic.csv`

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| 日期 | date | 否 | 流量自然日 |
| 渠道 | string | 否 | 线下门店 / 线上商城 / 小程序 / 直播 |
| 实验组 | string | 否 | 未分流 / 对照组 / 实验组;仅线上商城拆实验组与对照组 |
| 曝光人数 | int | 否 | 渠道当日曝光去重人数 |
| 访问人数 | int | 否 | 渠道当日访问去重人数,转化率分母 |
| 加购人数 | int | 否 | 当日加购人数,未按用户去重 |
| 下单人数 | int | 否 | 当日下单人数 |
| 支付人数 | int | 否 | 当日支付人数,转化率分子 |

## 7. 时间字段语义(下单 vs 支付 vs 发货)

| 字段 | 语义 | 默认用途 | 风险 |
|---|---|---|---|
| `orders.订单日期` | 下单自然日 | 日销趋势、新客首单月份 | 与支付日跨天时,趋势会与支付口径不一致 |
| `orders.支付时间` | 支付成功时间 | 支付口径 GMV、复购间隔 | 待支付 / 已取消为空,不能当 0 处理 |
| `orders.发货时间` | 出库时间 | 履约分析(本包指标暂不依赖) | 1% 缺失,不能当作未发货 |
| `users.注册日期` | 注册自然日 | 新客定义、cohort 分组 | 数据集起点前的历史订单不可见 |
| `traffic.日期` | 流量自然日 | 转化率趋势 | 与订单表无外键,只能按日期+渠道近似对齐 |

**强制要求**:同一份报告中的 GMV、订单数、客单价必须使用同一个「时间归属」口径(下单日或支付日),并在「口径与数据版本」中写明;不得一个指标按下单日、另一个按支付日。

## 8. 关联关系

```text
users (1) ──< orders (N) ──< order_items (N) >── (1) products
traffic: 独立聚合表,无外键;按 (日期, 渠道, 实验组) 与订单表近似对齐
```

| 关系 | 键 | 基数 | 用途 |
|---|---|---|---|
| 订单 → 明细 | `订单号` | 1:N | 连带率、品类结构 |
| 订单 → 用户 | `用户ID` | N:1 | 新客、复购、RFM、内部账号过滤 |
| 明细 → 商品 | `商品ID` | N:1 | 品类、价格带、品牌 |
| 流量 ↔ 订单 | `日期 + 渠道`(弱关联) | 非严格 | 漏斗对账,存在口径差 |

## 9. 脏数据规则

| 类型 | 识别条件 | 默认处理 | 影响指标 | 备注 |
|---|---|---|---|---|
| 测试单 | `orders.是否测试单 = 是` | 排除 | 全部规模 / 转化 / 留存指标 | 含内部账号与测试账号订单 |
| 内部账号 | `users.是否内部账号 = 是` | 排除 | 全部用户级指标 | 与测试单重叠时只计一次 |
| 测试账号 | `users.是否测试账号 = 是` | 排除 | 全部用户级指标 | 与内部账号互斥 |
| 刷单 | `orders.是否刷单 = 是` | 排除,保留审计 | 全部规模指标 | 报告中需给出刷单订单数 |
| 0 元单 | `orders.支付时间` 非空且 `支付金额 = 0` | 保留;`order_count` 计入,GMV 贡献 0 | `gmv`、`aov`、`attach_rate` | 是否计入订单数待确认(draft) |
| 待支付 / 已取消 | `订单状态` 属于待支付 / 已取消 | 支付口径排除 | `gmv`、`order_count` | 应付金额仍保留 |
| 全额退款 | `是否退款 = 是` 且 `退款金额 = 支付金额` | GMV 默认不扣;单独报退款率 | `gmv`、`aov`、`refund_rate` | 净 GMV 口径待确认 |
| 异常金额 | 支付金额明显偏离分布(如 > 100 倍中位数) | **只报告,不删除** | `gmv`、`aov` | 当前有 2 笔异常金额单 |
| 缺失值 | `orders.渠道` 1%、`orders.优惠金额` 2%、`orders.发货时间` 1%、`users.年龄` 3% | 保留;报告中列出缺失列与影响行数 | 渠道对比、客单价、年龄分层 | 不得静默填充 |
| 跨表不一致 | `order_items.商品ID` 不在 `products`、订单金额 ≠ 商品金额 + 运费 − 优惠 | 告警 | 品类结构、连带率 | 异常金额单属于已知例外 |
| 重复订单号 | `订单号` 重复 | 理论不存在(主键唯一) | 全部订单级指标 | 发现即按脏数据上报 |

## 10. 合成数据说明

- 生成脚本:`examples/generate_demo_data.py`;随机种子 `20260101`;
- 数据日期:2026-01-01 至 2026-03-31,共 90 天;
- 促销日:2026-01-20、2026-02-14、2026-03-08(流量与订单加权更高);
- 用户/商品/订单/明细/流量全部由脚本生成,不含任何真实姓名、手机号、地址或交易;
- 重新生成会覆盖 `examples/` 下同名 CSV;如需比对,请先备份或使用 git diff;
- 数据规模与指标参考值见 `README.md` 的「数据快照」一节。
